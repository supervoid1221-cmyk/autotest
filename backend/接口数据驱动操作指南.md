# 接口数据驱动操作指南

## 适用场景

当同一个接口需要用多组不同参数重复验证时，可在**接口管理 → 接口详情**启用“数据驱动”。平台会把每一行参数视为一次独立执行，并在场景运行、套件运行及报告中分别展示结果。

数据驱动适合批量验证：不同用户、金额、状态、分页参数、边界值等。它不替代场景编排：多个接口的上下游依赖仍应在场景中通过“数据提取 + 变量引用”完成。

## 配置步骤

1. 进入 **接口测试 → 接口管理**，新增或编辑一个接口。
2. 在“数据驱动”区域开启开关。
3. 在“字段名”填写本次数据集的列名，多个字段用英文逗号分隔，例如：

   ```text
   memberId, amount, remark
   ```

4. 点击“添加一行数据”，录入每组测试数据。
5. 在接口的请求头、Params、Data 或 JSON 请求体中，使用 `$ddt{字段名}` 引用同一行对应的值。
6. 点击“保存”，再通过场景或套件运行该接口。

场景步骤中的断言同样支持数据驱动。可在“期望值”中填写
`$ddt{expected_code}`，平台会使用当前数据行对应的期望值执行断言；断言描述、
数据提取变量名和提取表达式中也可以使用相同写法。

## 完整示例

字段名：

```text
memberId, amount, remark
```

数据行：

| memberId | amount | remark |
| --- | --- | --- |
| 10001 | 10 | 正常充值 |
| 10002 | 0 | 金额边界 |
| 10003 | -1 | 非法金额 |

JSON 请求体：

```json
{
  "memberId": "$ddt{memberId}",
  "amount": "$ddt{amount}",
  "remark": "$ddt{remark}"
}
```

执行时会展开为三次独立请求，报告名称依次类似：

```text
创建充值 [数据 1]
创建充值 [数据 2]
创建充值 [数据 3]
```

## 变量与数据驱动共用

数据驱动只识别 `$ddt{字段名}`，因此不会影响平台已有的变量能力：

| 用途 | 写法 | 说明 |
| --- | --- | --- |
| 当前数据行参数 | `$ddt{memberId}` | 仅在本行数据执行时替换 |
| 环境或提取变量 | `${token}`（推荐）、`{{token}}` | 由环境认证或前置接口数据提取提供 |
| 动态函数 | `${date("%Y-%m-%d")}` | 由动态函数管理提供 |

例如可以同时使用：

```json
{
  "memberId": "$ddt{memberId}",
  "requestNo": "${build_order_no}",
  "token": "${token}"
}
```

## 执行与报告

- 在场景详情直接运行接口时，Response 区域会显示每行数据的 HTTP 状态、耗时和通过/失败结果。
- 在套件运行时，每一行数据都会作为独立测试项写入原生执行报告。
- 一行失败不会阻止其余数据行继续执行；最终接口结果仅在所有数据行都通过时显示为通过。

## 使用注意事项

1. 字段名必须唯一，建议使用英文、数字和下划线，例如 `member_id`、`expected_code`。
2. 每行数据必须填写与字段名数量相同的列；空值可保留为空字符串。
3. 数据驱动当前用于“单接口多组数据”。若需要把多条接口按顺序串联，请使用场景管理。
4. 如果后续接口依赖前一接口返回值，请在前一接口配置数据提取，并在后续接口优先使用 `${变量名}`；也兼容 `{{变量名}}`。
5. 环境认证 Token 仍由“项目管理 → 环境与认证”统一管理；数据驱动不会复制或覆盖该认证逻辑。

## 常见问题

### 保存提示字段名重复

检查“字段名”输入框，删除重复名称后再次保存。

### 运行时没有按多行执行

确认已开启数据驱动、至少填写一行数据，并且请求参数中实际使用了 `$ddt{字段名}`。

### 报告中某一行失败

打开对应的 `[数据 N]` 测试项，检查该行的请求参数、响应正文和断言结果；其余数据行仍会继续执行。
