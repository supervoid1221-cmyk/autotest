# 自动化测试平台：接口录入操作手册

本文介绍如何将接口录入自动化测试平台，并配置项目环境、认证、参数、文件、场景变量及常见问题排查。

## 1. 录入前准备

接口必须归属于一个**项目**和一个**模块**。建议先完成以下配置：

1. 进入「项目管理 → 项目信息」，创建或确认目标项目。
2. 进入「项目管理 → 环境与认证」，为该项目配置执行环境，例如 Dev、Test、Pre、Prod。
3. 进入「接口测试 → 接口管理」，在左侧接口目录中选择项目，并在项目下创建模块，例如“用户管理”“订单管理”。

> 接口地址建议录入相对路径，例如 `/api/v2/user/profile`。执行时会自动拼接该接口所属项目、当前执行环境的 Base URL。

## 2. 配置项目环境与认证

路径：「项目管理 → 环境与认证」。

每个项目的同名环境独立保存 Base URL 和 Token。例如，项目 A 与项目 B 都可以有 Dev 环境，但两者的域名、账号和 Token 缓存彼此独立。

### 2.1 仅配置 Base URL

适用于无需登录或认证由接口参数自行处理的服务。

| 字段 | 示例 |
| --- | --- |
| 环境名称 | Dev |
| Base URL | `https://mgt-api-test.matchday.ink` |
| 启用自动登录 | 关闭 |

接口录入：

```text
/api/v2/fundAdjustment/create
```

实际请求：

```text
https://mgt-api-test.matchday.ink/api/v2/fundAdjustment/create
```

### 2.2 配置自动登录与 Token

适用于大部分需要登录态的接口。

| 字段 | 示例 |
| --- | --- |
| 启用自动登录 | 开启 |
| 登录接口 | `/api/v2/login` |
| 登录方法 | POST |
| 登录数据 | `{"userName":"tester","password":"***"}` |
| Token 提取表达式 | `$.data.token` |
| Token 请求头 | `x-token` 或 `Authorization` |
| Token 前缀 | `Bearer `；若使用 `x-token` 通常留空 |

平台规则：

- 执行接口时，按“**接口所属项目 + 执行环境名称**”定位环境。
- 平台从该环境登录并获取 Token；同一项目、同一环境共享缓存 Token，过期后才重新登录。
- 项目 A 的 Dev Token 不会用于项目 B；同名环境也不会互相串用。
- 环境 Token 优先于接口中保存的旧 `Authorization`、`x-token` 等认证头，避免录制数据中的过期 Token 覆盖环境认证。
- 修改环境地址、登录账号、登录参数或 Token 规则后，平台会自动清除旧 Token 并重新登录。

> `x-user-id`、`tenant-id`、`authority-id` 等业务身份头不一定能由 Token 自动推断。若服务端要求它们与 Token 身份一致，请使用与自动登录账号匹配的值；不要把用户 A 的 Token 与用户 B 的 `x-user-id` 混用。

## 3. 手动新增接口

路径：「接口测试 → 接口管理」。

1. 在左侧目录选择目标模块。
2. 点击「添加接口」。
3. 填写基本信息。
4. 配置请求头和请求数据。
5. 点击「保存」。

### 3.1 基本信息

| 字段 | 说明 |
| --- | --- |
| 项目 | 接口所属项目，决定执行时使用哪套环境和 Token。 |
| 所属模块 | 用于接口目录、筛选和场景选接口。 |
| 请求核心信息 | 左侧选择 GET、POST、PUT、PATCH、DELETE；右侧输入接口地址。 |
| 接口名称 | 用于列表、场景步骤与报告展示。 |

建议填写方式：

```text
项目：后台
模块：资金管理
接口名称：创建资金调整
方法：POST
地址：/api/v2/fundAdjustment/create
```

### 3.2 请求头

请求头使用 JSON 对象格式：

```json
{
  "accept": "application/json, text/plain, */*",
  "x-user-id": "365"
}
```

说明：

- `Content-Type` 通常无需手动填写。选择 JSON、Data 或文件上传时，平台会按请求类型处理。
- 已配置环境认证时，不要在接口中保存固定的 `Authorization`、`x-token`、`access-token` 等一次性 Token。
- 从浏览器复制的 `:authority`、`:method`、`:path`、`:scheme` 是 HTTP/2 伪请求头，不能手动填写，也不会被平台导入。
- 浏览器的 `cookie`、`host`、`content-length`、`sec-*`、`user-agent` 等运行时头无需录入。

## 4. 配置请求数据

接口详情中选择请求数据类型后，填写一个 JSON 对象。

### 4.1 Params（查询参数）

适用于 GET 查询或 URL 查询字符串。

```json
{
  "page": "1",
  "pageSize": "50",
  "status": "-999"
}
```

实际请求：

```text
GET /api/v2/withdrawal/list?page=1&pageSize=50&status=-999
```

### 4.2 JSON

适用于 `application/json` 请求体。

```json
{
  "id": "10054",
  "remark": "test",
  "status": 3
}
```

### 4.3 Data（表单数据）

适用于 `application/x-www-form-urlencoded` 或常规表单提交。

```json
{
  "userName": "tester",
  "password": "example"
}
```

### 4.4 上传文件

选择 Data（表单数据）后，可在文件上传区域上传文件。平台保存文件元信息，并在执行时以 `multipart/form-data` 发送。

注意：上传文件时不要手动写 `Content-Type: multipart/form-data`，否则浏览器/请求库无法自动补充 boundary。

## 5. 使用 cURL 导入接口

路径：「接口测试 → 接口管理 → Import」。

1. 在左侧接口目录先选择项目和模块，或在导入弹窗中手动选择。
2. 从 Postman、浏览器 Network 或命令行复制 cURL。
3. 粘贴到“cURL 内容”。
4. 点击“解析 cURL”。
5. 检查接口名称、请求方法、路径、请求头、请求数据类型及数据。
6. 点击“保存接口”。

示例：

```bash
curl --url 'https://example.com/api/v2/user/profile?page=1' \
  -H 'accept: application/json' \
  -H 'x-user-id: 365'
```

导入后：

```text
方法：GET
地址：/api/v2/user/profile
请求数据类型：Params
请求数据：{"page":"1"}
```

> 如果 cURL 的地址与项目环境 Base URL 相同，平台会保存相对路径；如果域名不同，请确认该接口是否确实需要访问独立域名。

## 6. 使用浏览器接口录制

平台支持通过 Chrome DevTools 录制网络请求，再批量导入接口。

### 6.1 安装录制扩展

1. 在 Chrome 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载未打包的扩展程序”。
4. 选择前端项目中的 `recorder-extension` 文件夹。

扩展目录：

```text
/Users/a1/Desktop/zl/测试平台前端/recorder-extension
```

### 6.2 录制并导入

1. 打开目标业务网站，按 `F12` 打开开发者工具。
2. 进入“接口录制”面板，点击“开始录制”。
3. 正常操作页面，触发需要录入的接口。
4. 点击“停止录制”。
5. 点击“下载 HAR”或“复制录制数据”。
6. 回到「接口测试 → 接口管理」，先选择目标模块，再点击“接口录制”。
7. 项目和模块会自动带入；粘贴录制数据或导入 HAR 文件。
8. 点击“解析录制数据”，勾选需要保存的请求。
9. 选择重复接口处理方式后，点击“保存接口”。

### 6.3 重复接口处理

| 方式 | 结果 |
| --- | --- |
| 忽略已存在接口 | 项目、模块、请求方法、路径相同的接口不保存。 |
| 覆盖已存在接口 | 用录制数据覆盖同一接口的名称、请求头和参数。 |
| 创建接口副本 | 保留原接口，并新增“录制”副本。 |

录制时会自动过滤浏览器运行时信息和 HTTP/2 伪请求头；认证 Token、Cookie、密码等敏感信息不会以原始值写入接口。

## 7. 在场景中串联接口变量

路径：「接口测试 → 场景管理 → 场景详情」。

### 7.1 上游接口：数据提取

在上游接口步骤的“数据提取”页签添加规则：

| 变量名 | 提取方式 | 响应来源 | 表达式 | 结果索引 |
| --- | --- | --- | --- | --- |
| token | JSONPath | JSON | `$.data.token` | 0 |
| userId | JSONPath | JSON | `$.data.userId` | 0 |

正则提取示例：

```text
表达式：token=(.*?)&
捕获组：1
```

### 7.2 下游接口：参数覆盖

后续步骤可以引用：

```json
{
  "userId": "${userId}",
  "token": "${token}"
}
```

推荐写法：

```text
${userId}
```

兼容写法：

```text
{{userId}}
```

### 7.3 智能关联

在下游接口步骤的“参数覆盖”页签中：

1. 平台展示前序接口已配置的数据提取变量。
2. 如果字段名或常见别名匹配，例如 `token / accessToken / authorization`、`userId / user_id`，会出现关联建议。
3. 点击单条“应用”，或点击“智能关联”批量应用。
4. 若先运行过上游接口，平台还会根据最近响应自动推荐“新增数据提取 + 下游变量引用”。

智能关联仅在确认后写入配置，不会自动覆盖已有参数。

## 8. 常见问题排查

### 8.1 `Invalid leading whitespace ... in header name: ':authority'`

原因：录入了浏览器 HTTP/2 伪请求头。

处理：删除以下字段：

```json
{
  ":authority": "...",
  ":method": "...",
  ":path": "...",
  ":scheme": "..."
}
```

新版录制导入和执行器会自动过滤它们。

### 8.2 `current account authority do not match`

原因：环境自动登录取得的 Token 身份，与接口中的 `x-user-id`、租户或权限主体不一致。

检查顺序：

1. 确认接口所属项目。
2. 确认运行时选择的环境名称。
3. 确认该项目同名环境的 Base URL 与 Postman 成功请求域名一致。
4. 确认环境登录账号与 Postman Token 对应的账号一致。
5. 检查接口中是否写死了不匹配的 `x-user-id`、`tenant-id`、`authority-id`。
6. 保存环境配置以清除旧 Token，再重新运行。

### 8.3 Postman 成功，平台失败

按以下内容逐项比对：

| 项目 | 必须一致的内容 |
| --- | --- |
| 域名 | 环境 Base URL 与实际调用域名。 |
| 请求方法 | GET、POST、PUT、PATCH、DELETE。 |
| 参数位置 | Params、Data、JSON 不可混放。 |
| 认证头 | `x-token` 或 `Authorization` 的名称及前缀。 |
| 身份头 | `x-user-id`、租户、权限主体等。 |
| 请求体类型 | JSON、表单、multipart 上传文件。 |

### 8.4 相对地址提示未选择环境

套件运行前必须选择执行环境；场景单接口运行前也必须选择运行环境。平台会按接口所属项目查找同名环境。

### 8.5 接口使用绝对地址

绝对地址不会拼接环境 Base URL，但仍会注入该接口所属项目、当前执行环境的认证 Token。建议确认该绝对地址与环境登录接口属于同一测试域和账号权限体系。

## 9. 推荐录入流程

```text
创建项目
  → 配置项目环境与认证
  → 创建模块
  → cURL 导入或浏览器录制导入接口
  → 运行单接口校验
  → 创建场景并编排接口顺序
  → 配置数据提取、变量关联与断言
  → 创建测试套件并选择执行环境
  → 执行并查看原生报告
```
