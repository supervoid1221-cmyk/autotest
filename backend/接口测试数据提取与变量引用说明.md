# 接口测试：数据提取与变量引用说明

## 1. 用途

数据提取用于从一个接口的响应中取出值，保存为变量，再在后续接口请求或断言中使用。典型场景包括：

- 登录接口提取 Token，后续接口在请求头中携带 Token；
- 创建数据后提取 ID，后续查询、修改或删除接口使用该 ID；
- 从响应中提取订单号、用户 ID、分页游标等业务数据。

## 2. 变量保存在哪里

每次运行测试套件时，后端都会创建独立目录：

```text
upload_yaml/result_{执行记录ID}_{时间戳}/
```

接口用例执行期间提取到的变量会保存为该目录中的：

```text
extract.yaml
```

例如：

```yaml
token: abc123
user_id: 371
```

该文件会随本次执行的 `artifacts.zip` 一起归档，可在前端的 **测试套件 → 执行结果 → 下载归档** 中下载查看。

## 3. 变量作用域

### 同一次套件执行

可以。接口测试用例在同一个 pytest 执行进程中共享同一份 `extract.yaml`，因此先执行的接口用例提取出的变量，可被后执行的接口用例引用。

```text
登录用例提取 token
        ↓
查询余额用例引用 ${token}
        ↓
创建订单用例提取 order_id
        ↓
查询/取消订单用例引用 ${order_id}
```

### 不同套件执行或下一次重新运行

不能依赖。每一次运行都会创建新的执行目录和新的 `extract.yaml`；变量不会自动跨执行记录共享。

### UI 测试用例

当前这套“数据提取”机制服务于接口 YAML 用例。UI 用例使用的是 Selenium 关键字框架，页面文本变量由其自身关键字逻辑处理，不能直接使用接口测试的 `extract.yaml` 变量。

## 4. 数据提取配置格式

在 **接口测试 → 场景管理 → 展开接口步骤 → 数据提取** 中填写 JSON 对象，默认 JSONPath 格式为：

```json
{
  "变量名": ["响应属性", "JSONPath 表达式", 结果索引]
}
```

字段说明：

| 位置 | 含义 | 示例 |
| --- | --- | --- |
| `变量名` | 保存变量的名称，后续优先以 `${变量名}` 引用 | `token` |
| `响应属性` | 响应中要查询的对象 | `json`、`headers`、`cookies` |
| `JSONPath 表达式` | 从对象中定位数据的路径 | `$.data.token` |
| `结果索引` | JSONPath 返回多个结果时取第几个，首个为 `0` | `0` |

### 正则表达式（re）提取

当响应不是 JSON，或需要从文本中截取值时，可使用以下格式：

```json
{
  "order_id": ["re", "text", "order_id=([A-Z0-9-]+)", 1]
}
```

| 位置 | 含义 | 示例 |
| --- | --- | --- |
| 第 1 项 | 固定写 `re` | `re` |
| 第 2 项 | 要搜索的响应属性 | `text`、`headers`、`json` |
| 第 3 项 | Python 正则表达式 | `order_id=([A-Z0-9-]+)` |
| 第 4 项 | 捕获组序号 | `1` 表示第一个括号捕获组 |

未匹配时变量值为 `no data`；正则语法或分组序号错误时，当前接口会明确执行失败。

## 5. 示例：登录后查询余额

### 5.1 登录接口的响应

假设登录接口返回：

```json
{
  "code": 200,
  "data": {
    "token": "abc123",
    "user": {
      "id": 371
    }
  }
}
```

登录用例的“数据提取”填写：

```json
{
  "token": ["json", "$.data.token", 0],
  "user_id": ["json", "$.data.user.id", 0]
}
```

执行后生成的 `extract.yaml`：

```yaml
token: abc123
user_id: 371
```

### 5.2 后续余额接口引用变量

在余额接口用例的请求头中填写：

```json
{
  "x-token": "${token}"
}
```

在查询参数中填写：

```json
{
  "userId": "${user_id}"
}
```

运行时，平台会将 `${token}` 和 `${user_id}` 替换为本次执行中提取到的实际值，再发送请求；`{{token}}` 写法也兼容。

## 6. JSONPath 常用写法

| 目标数据 | JSONPath |
| --- | --- |
| 顶层 `code` | `$.code` |
| `data` 中的 `token` | `$.data.token` |
| `data.user.id` | `$.data.user.id` |
| 数组第一个元素的 ID | `$.data.list[0].id` |
| 数组中所有 ID | `$.data.list[*].id` |

若表达式返回多个值，使用结果索引选择一个值。例如 `$.data.list[*].id` 返回多个 ID，索引 `0` 取第一个、`1` 取第二个。

## 7. 断言中的变量使用

`equals` / `contains` 等断言的期望值既可填写固定值，也可使用变量。例如：

```json
{
  "equals": {
    "用户 ID 一致": ["$.data.userId", "${user_id}"]
  }
}
```

断言实际值可使用 JSONPath 读取响应，期望值中的 `${user_id}` 会在断言前替换为本次执行已提取的变量值。

## 8. 注意事项

- 用例执行顺序很重要：引用变量的用例必须在提取变量的用例之后执行。
- 变量名建议使用英文、数字和下划线，例如 `access_token`、`order_id`，避免空格和特殊字符。
- 未提取到数据时，平台会写入 `no data`；后续请求若使用该变量，通常会导致接口校验失败。
- 响应不是 JSON 时，无法通过 `json` 提取业务字段；可根据实际情况尝试从 `headers` 或 `cookies` 中提取。
- Token、密码等敏感值会写入本次归档中的 `extract.yaml` 和可能的日志。归档下载、保留和共享时应按敏感数据处理。
- 当前变量文件以单次执行目录为边界，不会自动持久化为跨环境配置；公共固定配置建议使用接口定义、项目配置或安全的环境变量管理方式。
