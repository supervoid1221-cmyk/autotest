# 动态函数隔离与审批

## 1. 目标与执行链路

平台内置函数保持不变，用户编写的 Python 动态函数不在 Django API 或调度器主进程内执行。正式环境的链路为：

```text
backend / scheduler
  -> Unix Socket
  -> function-worker（容器无网络）
  -> 单次请求独立 Python 子进程
  -> JSON 结果
```

`function-worker` 不加入 Compose 网络，容器文件系统只读，去除 Linux capabilities，且每次调用都有 CPU、内存、文件大小、进程数和文件描述符限制。输入上限为 2 MB，输出上限为 1 MB，返回值必须能序列化为 JSON。

## 2. 审批规则

- 通过页面新建的动态函数默认为“待审批”，不会进入正式执行。
- 只有平台管理员可以审批或驳回。
- 修改代码、所属项目、超时时间或内存上限会使版本号加一，清空当前审批信息，并立即停止该函数用于正式执行。
- 审批通过时保存版本、代码 SHA-256、项目范围、资源上限、审批人和审批时间快照。已生成的版本快照不会被重复审批覆盖。
- 停用不修改审批快照，但停用期间不可执行。

## 3. 部署与升级

升级前先备份数据库和 `backend.env`，然后执行：

```bash
cd /home/deployer/test-platform
docker compose build backend scheduler function-worker
docker compose run --rm backend python manage.py migrate
docker compose run --rm backend python manage.py check
docker compose up -d --force-recreate function-worker backend scheduler web
docker compose ps
```

升级迁移会将已有动态函数标记为已审批的 v1，计算代码摘要并生成首个审计快照，以保持升级前的执行行为。

## 4. 环境变量

| 变量 | 生产建议 | 说明 |
| --- | --- | --- |
| `DYNAMIC_FUNCTION_SOCKET` | `/run/dynamic-functions/worker.sock` | backend、scheduler 和 worker 共享的 Unix Socket |
| `DYNAMIC_FUNCTION_TIMEOUT_SECONDS` | `3` | 默认超时，系统限制为 1–10 秒 |
| `DYNAMIC_FUNCTION_MEMORY_MB` | `128` | 默认内存上限，系统限制为 64–512 MB |
| `DYNAMIC_FUNCTION_ALLOW_LOCAL_FALLBACK` | `false` | 生产必须关闭，避免执行器不可用时降级到 backend 容器 |

开发环境可以将 fallback 设为 `true`，用于未启动 worker 时的本地调试；降级执行仍是单次请求独立子进程，但不具备容器级无网络隔离。

## 5. 验收与故障排查

启动后至少检查：

```bash
docker compose ps function-worker backend scheduler
docker compose exec backend test -S /run/dynamic-functions/worker.sock
docker compose logs --tail=200 function-worker backend scheduler
```

在页面新建一个只返回字符串的函数，确认它在审批前不可用，管理员审批后可执行，再修改代码并确认其回到待审批。

常见异常：

- “动态函数执行器不可用”：检查 `function-worker` 健康状态、Socket 文件、共享卷和两端路径是否一致。
- “超过 CPU 或内存限制”：先检查函数是否存在死循环或大对象构造；如确需增加资源，修改后必须重新审批。
- “返回值必须是可序列化的 JSON”：返回字符串、数字、布尔值、空值、列表或字典，不要返回 set、bytes 或自定义对象。
- Socket 存在但连接被拒绝：重启 `function-worker`，它会在启动时清理旧 Socket 并重新创建。

## 6. 回滚

应用与数据库必须回到同一发布点。如果新迁移已执行，不要单独回退代码后继续运行；按发布前数据库备份恢复，再启动对应版本的全部服务。共享卷 `dynamic-function-runtime` 只存放运行时 Socket，不存放业务数据，但仍不要使用 `docker compose down -v`。
