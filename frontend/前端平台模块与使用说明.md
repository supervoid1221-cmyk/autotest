# 模块与使用说明
## 启动  npm run dev 

## 1. 项目概览


本项目是“码尚测试平台”的 Web 管理端，基于 **Vue 3、TypeScript、Vite、Naive UI 和 Pinia** 构建，主要面向测试人员和项目管理人员。它通过 REST API 对接测试平台后端，提供项目、接口用例、UI 用例、测试套件、执行报告及基础组织信息的可视化管理能力。

核心业务链路：

```text
登录 → 组织/用户 → 项目 → 接口或 UI 用例 → 测试套件 → 执行结果与 Allure 报告
```

## 2. 启动与后端连接

### 环境要求

- Node.js 16 或更高版本
- 建议使用 pnpm（项目同时保留了 npm 锁文件）
- 已启动的后端服务，开发默认地址为 `http://127.0.0.1:8000`

### 常用命令

```bash
pnpm install
pnpm dev
pnpm build
pnpm preview
```

开发服务器默认端口为 `8001`。开发环境将浏览器请求的 `/api` 代理至后端的 `http://127.0.0.1:8000/api/`；因此前端一般通过 `http://127.0.0.1:8001` 打开。

相关配置位于：

| 文件 | 用途 |
| --- | --- |
| `.env` | 通用端口、应用名称和 Mock 开关 |
| `.env.development` | 开发环境 API 代理与接口基础地址 |
| `.env.production` | 构建环境变量 |
| `vite.config.ts` | Vite 服务、代理和构建配置 |

生产环境应将 `/api` 配置为由 Nginx 或网关转发到真实后端，而不要保留 `127.0.0.1:8000` 的开发代理。

## 3. 登录与会话机制

登录页路径为 `/login`。用户输入用户名和密码后，前端调用：

```text
POST /api/account/profile/login/
```

登录成功后，后端返回的 Token 会存入本地存储，有效期为 7 天。后续请求自动附带以下请求头：

```text
Authorization: Token <token>
```

退出登录会清除本地 Token 和用户资料。页面还提供自动锁屏能力；用户在非登录页持续无鼠标操作时会锁屏，重新操作后重新计时。

> 登录账号以实际后端数据库为准。不要使用模板 README 中的演示账号作为本平台的真实凭据。

## 4. 页面与业务模块

### 4.1 个人中心

| 菜单 | 路径 | 功能 |
| --- | --- | --- |
| 个人资料 | `/account/profile` | 修改昵称、查看/上传头像 |
| 修改密码 | `/account/reset_password` | 输入新密码和确认密码后提交 |

头像上传直接调用 `/api/account/profile/img_upload/`，并携带当前 Token。密码修改前端会校验两次输入是否一致，后端还会执行密码长度等规则校验。

### 4.2 系统设置

该模块用于配置测试平台内的组织信息，均提供列表、新建、编辑和删除操作。

| 菜单 | 路径 | 功能与主要字段 |
| --- | --- | --- |
| 部门设置 | `/system/department` | 部门名称、简介、负责人 |
| 职位设置 | `/system/position` | 职位名称、是否负责人 |
| 角色设置 | `/system/role` | 为用户关联部门和职位 |

通常先建立部门和职位，再创建用户角色；项目负责人和项目成员的选择列表来自平台用户资料。

### 4.3 项目管理

| 菜单 | 路径 | 功能 |
| --- | --- | --- |
| 项目信息 | `/project/project` | 管理项目名称、简介、项目地址、负责人和成员 |
| 项目配置 | `/project/config` | 将 pytest 的 `conftest` 脚本关联到项目 |

推荐先创建项目，再创建该项目的配置。项目是接口、UI 用例和测试套件的共同归属；创建后续测试资产时应选择正确项目。

### 4.4 接口测试

| 菜单 | 路径 | 功能 |
| --- | --- | --- |
| 接口管理 | `/case_api/endpoint` | 保存接口基础定义 |
| 用例管理 | `/case_api/case` | 基于接口定义编写可执行的接口用例 |

#### 接口管理

新增接口时选择项目，填写接口名称、HTTP 方法与 URL。页面中的请求编辑器按标签维护：

- 请求头（Headers）
- Cookie
- 查询字符串（Params）
- 表单参数（Data）
- JSON 请求体

键值参数通过动态表格编辑；JSON 请求体通过 JSON 编辑器维护。

#### 接口用例管理

创建用例时选择项目和目标接口，再配置：

| 配置项 | 用途 |
| --- | --- |
| Allure 标注 | 为报告补充标题、特性、故事、严重级别等键值信息 |
| 接口参数 | 覆盖或补充接口定义中的请求头、Cookie、查询参数、表单或 JSON 数据 |
| 数据提取 | 从响应属性中按表达式提取变量，供后续请求使用 |
| 断言 | 配置 `equals` 或 `contains` 断言，比较实际值与预期值 |

数据提取的每行由“变量名、响应属性、表达式、索引”组成；断言的每行由“断言名称、预期结果、比较方式、实际结果来源”组成。保存后的用例可加入测试套件运行。

### 4.5 UI 测试

| 菜单 | 路径 | 功能 |
| --- | --- | --- |
| 元素管理 | `/case_ui/element` | 管理页面元素定位信息 |
| 用例管理 | `/case_ui/case` | 用关键字步骤编排 UI 自动化用例 |

#### 元素管理

元素记录归属于某个项目，包含：元素名称、定位方式和定位表达式。定位方式是 Selenium 的标准枚举，例如 `ID`、`NAME`、`XPATH`、`CSS_SELECTOR`。

#### UI 用例管理

用例由项目、用例名称、fixture 列表和步骤组成。页面支持导入 Excel 格式的步骤并在表格中编辑。步骤结构为：

| 列 | 说明 |
| --- | --- |
| 序号 | 步骤顺序 |
| 步骤名 | 在执行日志/报告中显示的描述 |
| 关键字 | 要执行的 Selenium 关键字 |
| 参数 | 关键字的第一个参数 |
| 扩展参数 | Excel 额外列，会作为后续参数传递 |

界面内置关键字提示，包括设置浏览器、页面跳转、输入、清空、点击、文本保存、断言、iframe 进入/退出、下拉选择、JavaScript 执行和等待。实际可用关键字由后端执行框架决定，常用 Selenium fixture（例如 `chrome`）需写入 `usefixtures`。

### 4.6 测试套件

| 菜单 | 路径 | 功能 |
| --- | --- | --- |
| 套件管理 | `/suite/suite` | 编排同项目的 API/UI 用例，选择触发方式并执行 |
| 执行结果 | `/suite/run_result` | 查看运行状态、报告和下载归档 |

创建套件时：

1. 选择项目，填写套件名称和描述。
2. 从左右穿梭框中选择接口用例和 UI 用例。
3. 选择执行模式：
   - `单次执行`：可在套件列表点击“运行”。
   - `Cron`：填写 Cron 表达式，由后端调度器执行。
   - `WebHook`：使用后端生成或维护的 Hook 密钥，由外部系统调用。
4. 保存后，单次套件可在列表点击“运行”，后端会创建一条执行记录。

### 4.7 执行结果与报告

执行结果页面展示套件运行记录。每条记录支持：

- 点击“查看报告”：在前端内嵌页面加载后端提供的 Allure 报告。
- 点击“下载归档”：下载本次执行生成的 YAML、Excel、日志和其他产物 ZIP 包。

报告和归档 URL 均由后端执行结果返回，因此前端与后端应部署在可相互访问的同源或已正确配置跨域的地址下。

## 5. 前端架构

| 目录/文件 | 职责 |
| --- | --- |
| `src/main.ts` | 创建 Vue 应用，注册 Pinia、路由、Naive UI、全局指令 |
| `src/router/` | 路由、菜单、导航守卫；业务菜单位于 `router/modules/*.ts` |
| `src/views/` | 各模块页面和编辑表单 |
| `src/api/` | 后端接口访问层和 OpenAPI 生成的类型定义 |
| `src/utils/http/axios/` | Axios 实例、Token 注入、统一响应与错误处理 |
| `src/store/` | Pinia 状态，如用户、主题、标签页和锁屏状态 |
| `src/components/` | 通用表格、表单、上传、弹窗和 HTTP 用例编辑组件 |
| `src/layout/` | 主框架、菜单、页头、标签页和页脚 |

资源列表页复用 `BaseModelAPI` 与通用表格组件；因此项目、系统、接口、UI 用例和套件的新增、详情、修改、删除具有一致的交互方式。

## 6. 接口调用约定

前端 API 层统一以 `/api` 为基础地址，资源请求示例：

| 前端模块 | 请求前缀 |
| --- | --- |
| 账号 | `/api/account/` |
| 系统设置 | `/api/system/` |
| 项目 | `/api/project/` |
| 接口测试 | `/api/case_api/` |
| UI 测试 | `/api/case_ui/` |
| 测试套件 | `/api/suite/` |

Axios 期望后端统一返回：

```json
{
  "code": 200,
  "message": "ok",
  "result": {}
}
```

成功时前端默认直接取 `result`；列表分页则在 `result` 中读取 `itemCount`、`list`、`next` 和 `previous`。若要接入不同后端响应格式，优先调整 `src/utils/http/axios/index.ts` 中的响应转换逻辑。

## 7. 开发与部署注意事项

- `.env.development` 目前设置 `VITE_USE_MOCK=true`，但业务接口依赖真实 `/api` 代理；调试异常时应确认没有被 Mock 拦截。
- 当前 Token 保存在浏览器本地存储。生产环境应强制 HTTPS，并评估 XSS 防护与令牌失效策略。
- 前端请求超时为 10 秒。测试执行属于长任务，但“运行”接口只负责受理并返回执行记录；报告需在结果页稍后查看。
- 接口编辑页的 JSON 需要是合法 JSON；否则 JSON 编辑器在转换时会报错，无法保存。
- 后端需要为 Cron、Allure 和浏览器自动化准备运行环境；前端只负责配置和查看，不直接执行测试。
